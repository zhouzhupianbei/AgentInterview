## 一、AI 面试 AIGC Interview 核心考点

### 1.1 2026 年面试趋势变化

#### 新范式考察重点
- **Agent 架构设计**：从单纯调用 API 转向多 Agent 协作系统
- **RAG 进阶**：混合检索、查询改写、检索后处理成为标配
- **评估能力**：能设计评估体系、量化效果、分析 bad case
- **成本控制**：Token 优化、缓存策略、模型路由

#### 高频考点转移
```
2024 重点 → 2026 重点
- Prompt 技巧 → Agent 工作流设计
- 基础 RAG → 检索质量优化全链路
- 单模型调用 → 多模型路由与降级
- Demo 实现 → 生产级系统考量
```

### 1.2 AIGC 基础必考题

#### Transformer 核心
| 考点 | 深度要求 | 常见追问 |
|------|----------|----------|
| Self-Attention 复杂度 | O(n²·d) 推导 | FlashAttention 原理 |
| Positional Encoding | 绝对/相对位置编码区别 | RoPE 为什么适合长上下文 |
| LayerNorm | 与 BatchNorm 对比 | 为什么放在 Attention 前/后 |

#### 大模型架构演进
- **LLaMA 系列**：SwiGLU、RMSNorm、RoPE 的核心改进
- **MoE 架构**：稀疏专家混合、负载均衡、路由策略
- **长上下文**：Attention 稀疏化、KV Cache 优化、窗口注意力

### 1.3 实战排查题

```
场景：RAG 系统检索结果相关但答案质量差
排查思路：
1. 检索层：召回文档是否真的相关？(人工抽检)
2. 分块层：关键信息是否被切分破坏？
3. Prompt 层：指令是否清晰、有无示例？
4. 模型层：是否超出上下文窗口、有无截断？
5. 后处理：答案是否经过验证/引用标注？
```

## 三、系统设计面试题库

### 3.1 AI 系统特有考点

#### 与传统系统设计的区别
| 维度 | 传统系统 | AI 系统 |
|------|----------|----------|
| 核心瓶颈 | I/O、计算 | Token 成本、模型延迟 |
| 扩展方式 | 水平扩展 | 模型路由、缓存 |
| 一致性要求 | 强一致 | 可接受概率性 |
| 评估方式 | 功能测试 | 效果评估 + A/B 测试 |

### 3.2 经典题型与框架

#### 题型 1：设计 RAG 知识库系统
```
需求澄清要点:
- 文档规模 (万级/百万级)
- 文档类型 (PDF/Word/代码)
- 权限需求 (公开/细粒度)
- 响应时间 (秒级/亚秒级)

核心架构:
1. 文档处理层：解析 → 分块 → 嵌入
2. 索引层：向量索引 + 倒排索引
3. 检索层：混合检索 → 重排序 → 权限过滤
4. 生成层：Prompt 组装 → 模型调用 → 引用标注

关键决策点:
- 分块策略 (固定大小 vs 语义分块)
- 检索策略 (纯向量 vs 混合)
- 缓存策略 (查询缓存 vs 答案缓存)
```

#### 题型 2：设计高并发 AI 问答系统
```
核心挑战:
- 模型推理延迟 (首 Token 时间)
- 并发限流 (GPU 资源有限)
- 成本控制 (Token 消耗)

解决方案:
1. 异步处理：请求排队 + 流式响应
2. 模型路由：简单问题用小模型，复杂问题用大模型
3. 缓存层：相似查询复用答案
4. 降级策略：高峰期简化处理流程
```

#### 题型 3：设计多 Agent 协作系统
```
核心组件:
- Orchestrator：任务分解与分发
- Agent Registry：能力注册与发现
- Message Bus：Agent 间通信
- State Manager：对话状态管理

设计要点:
- Agent 职责边界清晰
- 通信协议标准化
- 错误处理与重试
- 可观测性 (日志/追踪/指标)
```

### 3.3 回答框架 (STAR 变体)

```
1. Clarify (澄清需求)
   - 用户规模、QPS、延迟要求
   - 功能范围、边界条件
   - 特殊约束 (成本、合规)

2. Challenge (点出挑战)
   - 这道题的核心难点
   - AI 系统特有的问题

3. Architecture (分层架构)
   - 从顶层到底层
   - 数据流向清晰

4. Decision (关键决策)
   - 为什么选 A 不选 B
   - 权衡考虑

5. Extension (扩展讨论)
   - 如果需求变化如何调整
   - 监控与评估方案
```

## 四、大模型开发面试专题

### 4.1 模型理解深度

#### 必须掌握的核心概念
- **Attention 机制**：计算过程、复杂度、优化方案
- **位置编码**：绝对/相对/RoPE 的原理与适用场景
- **归一化**：LayerNorm/RMSNorm 的区别
- **激活函数**：ReLU/GELU/SwiGLU 的演进

#### 进阶考点
- **KV Cache**：原理、内存占用、优化方案
- **FlashAttention**：IO 感知、分块计算
- **MoE**：专家路由、负载均衡、通信开销
- **量化**：INT8/INT4、校准、精度损失

### 4.2 微调与定制

#### 微调方法对比
| 方法 | 参数量 | 显存需求 | 适用场景 |
|------|--------|----------|----------|
| Full Fine-tune | 100% | 高 | 领域差异大、数据充足 |
| LoRA | 1-5% | 中 | 大多数场景 |
| QLoRA | 1-5% | 低 | 资源受限 |
| Prefix Tuning | <1% | 低 | 快速适配 |

#### 微调实战要点
```
数据准备:
- 数据质量 > 数据量
- 格式统一 (instruction-input-output)
- 去重与清洗

训练配置:
- Learning Rate: 1e-5 ~ 5e-5
- Batch Size: 根据显存调整
- Epochs: 3-5 (避免过拟合)

评估验证:
- 保留验证集
- 人工抽检生成质量
- 对比基线模型
```

### 4.3 部署与优化

#### 推理优化技术
- **量化**：FP16 → INT8 → INT4
- **剪枝**：结构化/非结构化剪枝
- **蒸馏**：大模型 → 小模型
- **编译优化**：vLLM、TensorRT-LLM

#### 服务化考量
```
延迟优化:
- 流式输出 (降低首 Token 时间)
- 批处理 (提高吞吐量)
- 缓存 (相似查询复用)

成本控制:
- 模型路由 (按难度分配)
- Token 限制 (防滥用)
- 降级策略 (高峰期)

可观测性:
- 请求日志 (输入/输出/延迟)
- 指标监控 (QPS、错误率、成本)
- 追踪系统 (全链路追踪)
```
