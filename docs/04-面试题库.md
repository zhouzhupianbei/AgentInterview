## 4.1 AIGC 基础题

### 【基础】Transformer 相关

#### Q1: Transformer 中 Self-Attention 的计算复杂度是多少？

**答案**：O(n² · d)

- n：序列长度
- d：模型维度

**推导**：
```
QK^T: (n×d) × (d×n) = O(n²·d)
softmax(QK^T): O(n²)
attention·V: (n×n) × (n×d) = O(n²·d)
总计：O(n²·d)
```

**优化方案**：
- FlashAttention：IO 感知，减少 HBM 访问
- Sparse Attention：只计算部分 attention
- Linear Attention：用 kernel trick 降为 O(n)

#### Q2: LayerNorm 和 BatchNorm 的区别？

**答案**：

| 维度 | BatchNorm | LayerNorm |
|------|-----------|-----------|
| 归一化维度 | batch 维度 | 特征维度 |
| 依赖 batch size | 是 | 否 |
| 训练/测试差异 | 需要 running stats | 一致 |
| 适用场景 | CNN | Transformer/RNN |

**代码对比**：
```python
# BatchNorm: 对 batch 维度统计
mean = x.mean(dim=0)  # [batch, seq, d] → [d]

# LayerNorm: 对特征维度统计
mean = x.mean(dim=-1, keepdim=True)  # [batch, seq, d] → [batch, seq, 1]
```

### 【基础】大模型相关

#### Q3: LLaMA 使用了哪些改进？

**答案**：

1. **RoPE 位置编码**：更好的长度外推性
2. **SwiGLU 激活**：替代 ReLU，效果更好
3. **Pre-Normalization**：LayerNorm 放在子层前
4. **RMSNorm**：简化版 LayerNorm，更快

**SwiGLU 公式**：
```
SwiGLU(x) = Swish(xW) ⊗ (xV)
其中 Swish(x) = x · sigmoid(βx)
```

#### Q4: 什么是 KV Cache？如何节省显存？

**答案**：

**KV Cache**：缓存已生成 token 的 K/V，避免重复计算

**显存计算**：
```
对于 LLaMA-7B (32 层，d=4096, 32 heads):
每层每 token 的 KV cache:
  2 × 32 heads × (4096/32) × 4 bytes = 32KB
  
生成 1000 tokens:
  32 层 × 32KB × 1000 = 1GB
```

**优化方法**：
1. **量化**：FP16 → INT8，节省 50%
2. **MQA/GQA**：共享 K/V heads
3. **Offload**：部分 cache 放到 CPU 内存

### 【实战】代码题

#### Q11: 实现一个简单的 RAG 系统

**参考答案**：

```python
from langchain.embeddings import OpenAIEmbeddings
from langchain.vectorstores import Chroma
from langchain.chat_models import ChatOpenAI
from langchain.chains import RetrievalQA

class SimpleRAG:
    def __init__(self, docs_dir="./docs"):
        # 1. 加载文档
        self.documents = self.load_docs(docs_dir)
        
        # 2. 创建向量库
        self.embeddings = OpenAIEmbeddings()
        self.vectorstore = Chroma.from_documents(
            documents=self.documents,
            embedding=self.embeddings,
            persist_directory="./chroma"
        )
        
        # 3. 创建 QA chain
        self.llm = ChatOpenAI(model="gpt-4", temperature=0)
        self.qa_chain = RetrievalQA.from_chain_type(
            llm=self.llm,
            retriever=self.vectorstore.as_retriever(search_kwargs={"k": 3})
        )
    
    def load_docs(self, docs_dir):
        from langchain.document_loaders import DirectoryLoader
        loader = DirectoryLoader(docs_dir, glob="**/*.md")
        return loader.load()
    
    def query(self, question):
        result = self.qa_chain({"query": question})
        return {
            "answer": result["result"],
            "sources": [doc.page_content for doc in result["source_documents"]]
        }

# 使用
rag = SimpleRAG()
response = rag.query("什么是 Transformer？")
print(response["answer"])
```

#### Q12: 实现 Agent 的工具调用解析

**参考答案**：

```python
import json
import re

class ToolCaller:
    def __init__(self):
        self.tools = {
            "search": self.search_web,
            "calculate": self.calculate,
            "get_weather": self.get_weather
        }
    
    def parse_and_call(self, llm_response):
        """
        解析 LLM 输出并调用工具
        格式：Action: tool_name[arguments]
        """
        pattern = r"Action:\s*(\w+)\[(.*?)\]"
        match = re.search(pattern, llm_response)
        
        if not match:
            return None, "No action found"
        
        tool_name, args_str = match.groups()
        
        if tool_name not in self.tools:
            return None, f"Unknown tool: {tool_name}"
        
        try:
            args = json.loads(args_str)
            result = self.tools[tool_name](**args)
            return result, None
        except Exception as e:
            return None, f"Error: {str(e)}"
    
    def search_web(self, query):
        # 实现搜索逻辑
        return f"搜索结果：关于{query}的信息..."
    
    def calculate(self, expression):
        return eval(expression)  # 注意：生产环境需要沙箱
    
    def get_weather(self, city):
        return f"{city}今天天气晴朗，25°C"

# 使用
caller = ToolCaller()
llm_output = """
Thought: 我需要搜索信息
Action: search_web[{"query": "AI Agent 教程"}]
"""
result, error = caller.parse_and_call(llm_output)
```

## 4.7 2026 新技术题

### 【前沿】MCP (Model Context Protocol)

#### Q17: 什么是 MCP？它解决了什么问题？

**参考答案**：

**MCP（Model Context Protocol）** 是 2026 年新兴的开放协议，用于标准化 LLM 应用与外部工具/数据源的集成。

**解决的问题**：
1. **碎片化**：之前每个框架都有自己的工具调用方式
2. **互操作性**：不同工具之间无法互通
3. **安全性**：缺少统一的权限控制标准
4. **开发成本**：每次集成新工具都要重写代码

**核心架构**：
```
┌─────────────┐         ┌─────────────┐
│   LLM App   │◄───────►│  MCP Host   │
│  (Client)   │         │  (协调器)    │
└─────────────┘         └──────┬──────┘
                               │
                    ┌──────────┼──────────┐
                    │          │          │
              ┌─────▼────┐ ┌──▼────┐ ┌──▼────┐
              │ MCP Svr  │ │ MCP Svr│ │ MCP Svr│
              │ (文件)    │ │(数据库)│ │ (API)  │
              └──────────┘ └───────┘ └───────┘
```

**对比 Function Calling**：
| 维度 | Function Calling | MCP |
|------|-----------------|-----|
| 标准 | 各厂商私有 | 开放标准 |
| 语言 | 依赖 SDK | 多语言支持 |
| 发现 | 手动注册 | 自动发现 |
| 安全 | 各自实现 | 统一模型 |

#### Q18: 如何实现一个 MCP 服务器？

**参考答案**：

**Python 示例**：
```python
from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp.types import Tool, TextContent

server = Server("example-server")

@server.list_tools()
async def list_tools():
    return [
        Tool(
            name="calculate",
            description="执行数学计算",
            inputSchema={
                "type": "object",
                "properties": {
                    "expression": {"type": "string"}
                }
            }
        )
    ]

@server.call_tool()
async def call_tool(name, args):
    if name == "calculate":
        result = eval(args["expression"])
        return [TextContent(type="text", text=str(result))]

async def main():
    async with stdio_server() as (read, write):
        await server.run(read, write)

if __name__ == "__main__":
    import asyncio
    asyncio.run(main())
```

**关键点**：
1. 定义工具元数据（名称、描述、参数）
2. 实现工具调用逻辑
3. 使用标准 IO 或 SSE 通信
4. 处理权限和错误

### 【前沿】GraphRAG

#### Q19: GraphRAG 相比传统 RAG 有什么优势？

**参考答案**：

**传统 RAG 的局限**：
1. **碎片化**：检索独立片段，丢失全局信息
2. **无法推理**：难以回答需要多跳推理的问题
3. **实体混淆**：同名实体无法区分
4. **关系缺失**：无法理解实体间关系

**GraphRAG 的优势**：
```
传统 RAG:
问题 → 检索片段 → 生成答案
        ↓
    可能丢失上下文

GraphRAG:
问题 → 检索实体 → 遍历关系 → 子图 → 生成答案
              ↓
          知识图谱
```

**核心流程**：
1. **索引阶段**：
   - 提取实体和关系
   - 构建知识图谱
   - 生成社区摘要

2. **检索阶段**：
   - 实体链接
   - 关系遍历
   - 子图提取

3. **生成阶段**：
   - 基于子图生成
   - 引用图谱证据

**适用场景**：
- ✅ 长文档分析（报告、论文）
- ✅ 跨文档推理
- ✅ 复杂问答（需要多步推理）
- ❌ 简单事实查询（杀鸡用牛刀）

**成本考虑**：
- 索引成本：比传统 RAG 高 5-10 倍
- 检索成本：略高（需要图遍历）
- 建议：只对核心文档使用 GraphRAG

#### Q22: 如何设计一个 Agentic Skills 系统？

**参考答案**：

**设计原则**：
1. **单一职责**：每个技能只做一件事，做好一件事
2. **可组合性**：技能可以像乐高一样组合
3. **可测试性**：技能可以独立测试和验证
4. **可观测性**：技能执行过程可追踪、可调试

**接口设计**：
```python
from abc import ABC, abstractmethod
from typing import Any, Dict, Optional

class Skill(ABC):
    """Agentic Skill 基类"""
    
    @property
    @abstractmethod
    def name(self) -> str:
        """技能名称"""
        pass
    
    @property
    @abstractmethod
    def description(self) -> str:
        """技能描述"""
        pass
    
    @property
    @abstractmethod
    def parameters(self) -> Dict[str, Any]:
        """参数 schema"""
        pass
    
    @abstractmethod
    async def execute(self, **kwargs) -> Dict[str, Any]:
        """执行技能"""
        pass
    
    async def validate(self, **kwargs) -> bool:
        """验证参数"""
        return True
    
    async def rollback(self, context: Dict) -> None:
        """回滚操作（可选）"""
        pass

# 示例：搜索技能
class WebSearchSkill(Skill):
    @property
    def name(self) -> str:
        return "web_search"
    
    @property
    def description(self) -> str:
        return "搜索互联网获取信息"
    
    @property
    def parameters(self) -> Dict[str, Any]:
        return {
            "query": {"type": "string", "required": True},
            "limit": {"type": "integer", "default": 5}
        }
    
    async def execute(self, query: str, limit: int = 5):
        results = await search_web(query, limit)
        return {"results": results, "count": len(results)}
```

**技能组合**：
```python
class SkillComposer:
    def __init__(self):
        self.skills: Dict[str, Skill] = {}
    
    def register(self, skill: Skill):

    def chain(self, *skill_names: str):
```

### 【前沿】SuperClaude Framework

#### Q23: 什么是 SuperClaude_Framework？它如何增强 Claude Code？

**参考答案**：

**SuperClaude_Framework** 是一个配置框架，通过 specialized commands（专业命令）、cognitive personas（认知角色）和 development methodologies（开发方法论）来增强 Claude Code 的能力。

**核心组件**：
1. **Cognitive Personas（认知角色）**：
   - 为不同任务定义专门的 AI 角色
   - 例如：代码审查员、架构师、测试工程师
   - 每个角色有特定的系统提示和行为模式

2. **Specialized Commands（专业命令）**：
   - 预定义的命令模板，简化常见工作流
   - 例如：`/review`、`/refactor`、`/test`
   - 支持参数化和组合

3. **Development Methodologies（开发方法论）**：
   - 集成的开发流程和最佳实践
   - 例如：TDD、代码审查流程、重构策略

### 【前沿】Agentic RAG

#### Q25: 如何实现 Agentic RAG？

**参考答案**：

**Agentic RAG** = Agent 自主决策 + RAG 检索增强

**核心思路**：让 Agent 自主决定何时检索、检索什么、如何整合

**实现框架**：
```python
from langchain.agents import AgentExecutor
from langchain.tools import Tool

class AgenticRAG:
    def __init__(self, vectorstore, llm):
        self.vectorstore = vectorstore
        self.llm = llm
        
        # 定义检索工具
        self.tools = [
            Tool(
                name="search",
                func=self.search,
                description="搜索知识库"
            ),
            Tool(
                name="verify",
                func=self.verify,
                description="验证信息准确性"
            )
        ]
    
    def search(self, query):
        # 自主决定检索策略
        results = self.vectorstore.similarity_search(query, k=5)
        # 质量评估
        if self.is_insufficient(results):
            # 改写查询，再次检索
            new_query = self.rewrite_query(query)
            results += self.vectorstore.similarity_search(new_query, k=3)
        return self.format_results(results)
    
    def verify(self, information):
        # 交叉验证
        return self.cross_check(information)
    
    def query(self, question):
        # Agent 自主决策流程
        prompt = f"""
        你需要回答：{question}
        
        可用的工具：
        - search: 搜索知识库
        - verify: 验证信息
        
        请自主决定使用哪些工具，如何使用。
        """
        return self.llm.generate(prompt)
```

**关键能力**：
1. **自主检索决策**：决定何时检索、检索几次
2. **动态策略调整**：根据结果质量调整策略
3. **多源融合**：整合多个检索结果
4. **自我验证**：检查答案可靠性

**面试考点**：
- 如何评估检索结果质量
- 如何处理检索结果冲突
- 如何平衡检索成本和答案质量

#### Q15: 实现 Top K 问题（堆）

```python
import heapq

def topKFrequent(nums, k):
    """
    LeetCode 347. Top K Frequent Elements
    """
    # 统计频率
    from collections import Counter
    count = Counter(nums)
    
    # 维护大小为 k 的小顶堆
    heap = []
    for num, freq in count.items():
        if len(heap) < k:
            heapq.heappush(heap, (freq, num))
        elif freq > heap[0][0]:
            heapq.heapreplace(heap, (freq, num))
    
    return [num for freq, num in heap]

# 时间复杂度：O(n log k)
# 空间复杂度：O(n)
```

#### Q16: 实现 Attention 机制

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class ScaledDotProductAttention(nn.Module):
    def __init__(self, d_model):
        super().__init__()
        self.scale = d_model ** 0.5
    
    def forward(self, Q, K, V, mask=None):
        # Q, K, V: [batch, seq_len, d_model]
        scores = torch.matmul(Q, K.transpose(-2, -1)) / self.scale
        
        if mask is not None:
            scores = scores.masked_fill(mask == 0, -1e9)
        
        attn = F.softmax(scores, dim=-1)
        output = torch.matmul(attn, V)
        
        return output, attn

# 使用
attention = ScaledDotProductAttention(d_model=512)
output, attn_weights = attention(Q, K, V)
```
