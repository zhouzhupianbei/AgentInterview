# 知识卡片 - 2026-04-01

## 主题：系统设计题不是考"背架构"，而是考"决策理由"

### 核心观察

这轮维护新增了完整的系统设计题案例库，源于一个持续的观察：

**很多候选人在系统设计题上失分，不是因为不知道组件名称，而是因为讲不清"为什么这样选"。**

面试官问系统设计，真正想听的是：
- 你能不能把零散知识串成方案
- 你能不能权衡不同选择
- 你能不能考虑边界情况和扩展性

而不是：
- 背出某个标准架构
- 罗列一堆技术名词
- 画一个复杂但说不清的图

---

### 系统设计题的通用框架

```
1. 需求澄清 —— 确认范围，不要一上来就画架构
2. 核心挑战 —— 点出这道题的难点在哪里
3. 架构设计 —— 分层讲，不要一锅端
4. 关键决策 —— 为什么这样选，有没有考虑过其他方案
5. 扩展与权衡 —— 如果 XX 变了，架构要怎么调整
```

这个框架的价值在于：
- **需求澄清** 让面试官知道你理解问题边界
- **核心挑战** 展示你抓重点的能力
- **架构设计** 体现系统思维（分层、模块、数据流）
- **关键决策** 拉开差距的核心（有判断 vs 没判断）
- **扩展权衡** 展示你考虑过边界情况

### 5 个完整案例覆盖的场景

| 案例 | 核心挑战 | 关键决策 |
|------|----------|----------|
| 企业知识库系统 | 检索质量、权限控制、文档多样性 | 混合检索、按类型分块、检索后过滤权限 |
| AI 代码审查助手 | 误报率控制、上下文理解、集成流程 | 规则+AI 混合、AST 解析、人工确认机制 |

| AI 成本监控系统 | Token 准确计数、告警策略、优化建议 | SDK 埋点、三层告警、数据驱动建议 |
| RAG 评估平台 | 答案质量评估、评估集管理、A/B 测试 | 三层评估（自动 + 人工 + 反馈）、版本管理、显著性检验 |

### 面试回答的核心技巧

#### 1. 每道题准备 3 个关键决策理由

比如企业知识库系统：
- 为什么用混合检索？→ 纯向量对专业术语效果差
- 为什么按类型分块？→ 统一分块会割裂上下文
- 为什么检索后过滤权限？→ 避免漏掉相关内容

#### 2. 用"对比"展示判断

不要只说"我选了 A"，要说：
- "我考虑过 A 和 B"
- "A 的優勢是...，B 的优势是..."
- "在这个场景下，我选 A 因为..."

#### 3. 主动提扩展与权衡

展示你考虑过边界情况：
- "如果文档量从 10 万增加到 1000 万，我会..."
- "如果响应时间要求从秒级降到毫秒级，需要..."
- "如果需要支持多语言，Embedding 模型要换..."

### 练习建议

1. **先自己尝试回答**，再看参考答案
2. **强制自己画草图**，培养系统思维
3. **每道题准备 3 个关键决策理由**
4. **找人对练**，让对方追问"为什么"
5. **录音听自己的回答**，删掉冗余词

---

### 与面试表达专题的衔接

系统设计题是面试表达的综合应用：
- **概念解释** → 用三层表达法讲清楚每个组件
- **项目经验** → 用 STAR 框架讲自己做过的系统
- **判断观点** → 用"价值 - 核心 - 局限"框架讲技术选型

所以建议学习顺序：
1. 先看 [08-面试表达专题](./docs/08-面试表达专题.md) 学框架
2. 再看 [09-系统设计题案例库](./docs/09-系统设计题案例库.md) 练应用
3. 最后找实际题目对练
