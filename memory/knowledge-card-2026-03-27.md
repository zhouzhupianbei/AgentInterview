# 知识卡片 - 2026-03-27

## 主题：知识库型仓库的"正文层"价值

### 核心观察

这一轮维护下来，一个越来越清晰的判断是：**知识型 GitHub 仓库最容易出现的假繁荣，是首页越来越完整、资料页越来越多，但正文层始终偏薄。**

很多仓库看起来什么都全：
- README 有导航、有学习路径、有模块入口
- resources 有几十上百条资料，分类清晰
- 但点进 docs 正文，发现只有标题和提纲

这种仓库的读者体验是："知道该看什么，但看不到足够深入的内容"。

### 为什么正文层容易被忽视

1. **正文难写**：写 README 是整理，写 resources 是收集，写 docs 正文是创作
2. **反馈慢**：正文写出来不像新增资料那样"立竿见影"
3. **容易拖延**："先把框架搭好，正文以后补"——然后就一直没补

### 正文层的价值

正文层是知识库的"护城河"：
- README 别人可以抄，resources 别人可以收集
- 但正文里的理解、判断、案例，是抄不走的

更重要的是：**正文层是读者真正能获得认知提升的地方**。
