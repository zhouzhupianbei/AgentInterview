### Level 2: Vibe Coding 定义与起源

#### Level 3: 什么是 Vibe Coding ⭐

**📖 核心概念**
Vibe Coding（氛围编程）是由 Andrej Karpathy 提出的编程新范式，核心理念是"fully give in to the vibes"——完全信任 AI，以自然语言对话的方式编程，让 AI 处理代码细节。它不是简单的"用 AI 写代码"，而是一种新型心流体验：编程变得像创作一样流畅，AI 成为思维的延伸而非工具。

**❓ 常见面试题**
1. Vibe Coding 与传统编程的本质区别是什么？
2. 为什么说 Vibe Coding 是"心流体验"而非工具使用？

**✅ 参考答案要点**
- 传统编程：人写代码，AI 辅助补全
- Vibe Coding：人描述意图，AI 生成完整实现
- 心流特征：想法直接变产品，无需关注语法细节
- 认知转变：从"写代码"到"设计系统"

### Level 2: Vibe Coding 的局限性与挑战

#### Level 3: Vibe Coding 的三大局限 ⭐⭐

**📖 核心概念**
Vibe Coding 存在三大局限：(1) 调试困难——用户不知道代码怎么跑起来的，排查无从下手；(2) 工程鸿沟——AI 项目失败率高达 67%，85% 企业面临人才短缺；(3) 知识黑盒——用户无法理解底层实现，难以优化和维护。这些局限催生了 SDD 规范驱动开发的兴起。

**❓ 常见面试题**
1. 为什么 Vibe Coding 项目失败率高达 67%？
2. 如何平衡 AI 辅助与代码理解？

**✅ 参考答案要点**
- 调试困难：缺乏代码生成过程的可解释性
- 工程鸿沟：直觉驱动无法应对复杂系统
- 知识黑盒：用户技能退化，无法独立维护
- 解决方向：SDD 规范驱动 + Harness Engineering

#### Level 3: 从 Vibe Coding 到 Harness Engineering ⭐⭐⭐

**📖 核心概念**
Harness Engineering（系统驾驭）是 Vibe Coding 的演进方向，2026 年新兴范式。核心转变：不是让 AI"消失"，而是让开发者成为"AI 驾驭者"。关注系统设计 > 代码实现，产品感 > 编程技能。开发者角色从"写代码"转向"设计系统、调试 AI、定义规范"。

**❓ 常见面试题**
1. Harness Engineering 与 Vibe Coding 的本质区别？
2. AI 时代开发者需要哪些新技能？

**✅ 参考答案要点**
- Vibe Coding：直觉驱动，完全信任 AI
- Harness Engineering：系统驾驭，AI 为工具
- 新技能：系统设计、产品感、规范编写、AI 调试
- 角色转变：从实现者到设计者和审核者
